Slowest Link

Finds the recovery promises a system can't keep: each promise in a continuity plan, checked against everything the function depends on.

The system is the OpenTelemetry Astronomy Shop, run for real: its published architecture, 1,037 of its traces, and an outage test on every component.

How long until each function is back

Each line is a function, drawn to scale. Its stations are the components it waits for, in restore order, dependencies first. The tick is the function's promise. Red marks the time past it, and the ringed station is the slowest link.

An outage notice arrives

Paste a status-page notice. Relate's full-text search finds the components it describes. The graph then finds the functions behind them, the promises that break and the restore order.

Before a change merges

A new call between two services can put a slow component under a fast promise. The guard tries the call on a copy of the plan and reports what it would break. The same check runs in CI and as a coding-agent hook.

Measured on the running shop

Each component was stopped for 60 seconds while every journey was replayed through the front door. A dot means the function went down. A red cell means the evidence view, frozen before the tests ran, said otherwise.
